Fake AI tool download to fileless infostealer: endpoint compromise

An employee followed a fake install page for an AI coding tool and pasted a command into PowerShell. I rebuilt the full attack chain from EDR telemetry, found what was at risk, and drove containment, credential rotation and new detections.

Overview

An employee searched for an AI coding tool, clicked a malicious ad, and landed on a convincing fake download page. The page put a command on their clipboard and told them to paste it into a terminal to "install" the tool.

That one paste launched a fileless payload that ran entirely in memory. The compromise only surfaced days later, when the employee got a notice that their browser-saved passwords had leaked. I reconstructed what ran, what it could reach, and what had to be rotated.

Why this matters for an IR analyst

  • ClickFix is one of the most common initial-access techniques right now. There is no exploit and no attachment, just a user pasting a command, which slips past most email and web controls.
  • Fileless means the evidence is in telemetry, not on disk. The whole case rests on reading process trees and command history well.
  • Scoping drives the response. Knowing exactly what the payload could reach decides which credentials to rotate and how far to go.
  • Interview answer: "Walk me through an endpoint compromise from detection to closure" is a standard IR question. This page is a worked answer.

Scenario

TriggerEmployee report of a leaked-password notice, matched to EDR detections on their laptop
Initial accessMalicious search ad leading to a fake AI tool download page (ClickFix lure)
ExecutionUser pasted a command into PowerShell, which launched mshta to fetch and run a remote HTA payload in memory
EnvironmentCorporate Windows laptop, SSO-joined, with a Git client holding live sessions to internal code hosting
GoalRebuild the attack chain, scope what was exposed, contain, and close the detection gap

Walkthrough

  1. Contain first

    Once the employee's report was matched to EDR detections on their laptop, the host was network-contained from the EDR console and a full wipe and reimage was requested from IT.

  2. Rebuild the process tree

    I pulled process telemetry for the infection window and walked the chain: browser activity on the lure page, then a terminal and PowerShell opened by the user, then mshta fetching a remote payload. There were two waves, because the user ran the command a second time when nothing seemed to happen.

    #event_simpleName=ProcessRollup2 FileName="mshta.exe"
| ParentBaseFileName="powershell.exe"
| table([@timestamp, ParentBaseFileName, FileName, CommandLine])

    mshta is a signed Windows binary (a "living off the land" tool), so the attack used no malware file at the moment of execution.

  3. Confirm exactly what was typed

    EDR command-history events showed each PowerShell session ran a single command: the pasted lure command, word for word. That ruled out an attacker typing anything else on the machine.

  4. Look for defense evasion

    The payload tried to open a handle to the EDR sensor process (an attempt to tamper with it, which failed) and later wrote a binary with a misleading file extension. Both went on the timeline as evasion steps.

  5. Hunt for credential harvesting

    I audited every non-routine process across the window, filtering for classic credential-dumping behaviour: LSASS access, procdump, and command-line download tools. None was found. That, plus browser activity in a short window after execution, pointed to theft of browser-stored data rather than OS credential dumping.

    #event_simpleName=ProcessRollup2
| FileName=/(procdump|rundll32|curl|certutil)\.exe/i
   OR CommandLine=/lsass/i
| table([@timestamp, ParentBaseFileName, FileName, CommandLine])

  6. Scope what was at risk

    From the user's context, the payload could reach browser-saved passwords and session cookies, live SSO session tokens, SSH keys used by the Git client, and the Windows credential store. That list decided the rotation plan.

  7. Rotate everything in scope

    The user's SSO password was reset and all active sessions revoked, browser-saved and personal passwords were changed, and Git access tokens and SSH keys were rotated. The employee and their manager got a written summary with required actions.

  8. Attribute and enrich

    The lure and delivery matched a publicly reported infostealer campaign that uses fake AI tool sites to target developers. A sandbox run of the lure confirmed the clipboard-injection behaviour.

  9. Close the detection gap

    IOCs and behavioural patterns (domains, payload URL, the PowerShell-to-mshta chain) went into the EDR for automated detection. A prevention-gap review was raised with the EDR vendor, and credential-leak monitoring confirmed no exposure of corporate accounts or the device.

Outcome

  • Full attack chain reconstructed from telemetry, from lure page to in-memory payload
  • Hands-on-keyboard attacker activity ruled out from command history
  • Credential dumping ruled out; browser data identified as the likely loss
  • Host contained and reimaged; SSO, browser, Git and SSH credentials rotated
  • New behavioural detections in place and a prevention-gap review raised with the EDR vendor
